# Sub2API STATE Kit 插件

本仓库维护 Sub2API `v0.2.8` 的独立 `.s2plugin` 插件，不覆盖宿主源码。`4.7.0` 只维护 Cookie + `780` 滚动票据，正式配置不能再启用 292/332；旧配置保存时自动迁移。质量探针支持 `strict_fallback`、`strict` 和 `off`，并新增 1 到 3 路并发打票。

返回新的 `780` 只是会话滚动，不能单独作为降智判定；网关、出口 IP、Cookie 和 `server_is_overloaded` 也不是永久“不降智白名单”。香港和未知出口始终拒绝。

## 最短配置

1. 填写第一层 S5/HTTP 代理，用于访问代理生成器。
2. 打票出口选择“代理生成器 API”或“S5/HTTP 固定采集代理”。
3. 业务固定代理留空时使用第一层，也可以填写独立出口。
4. 质量探针选择“严格优先 + 临时票保活（推荐）”，填写提示词和通过答案。
5. 账号只需选择开关、Pro/Team 和模型，不再配置账号级旧出口方式。
6. 保存后等待状态为“可用”或“可用 · 未通过质量”，再用实际模型请求验收。

| 质量模式 | 行为 | 适用场景 |
| --- | --- | --- |
| `strict_fallback` | 先找严格合格票；没有旧票时先发布临时票保活，后台继续升级 | 推荐，避免探针未命中导致服务中断 |
| `strict` | 只发布回答命中通过答案的票 | 可以接受短暂无票，只追求严格质量 |
| `off` | 不执行质量问答 | 只做链路和模型复验 |

临时票会在状态页明确显示“临时票 · 未通过质量”，不会伪装成严格合格票。严格合格票找到后会立即替换临时票。

## 请求环境统一

配置页新增“统一请求环境日期、时区与语言”开关，默认关闭。打开后：

- 请求里已经存在的 `<current_date>`、`<timezone>` 和 `user_location.timezone` 会按账号时区统一；
- 已经存在的 `Accept-Language` 会替换为 `en-US,en;q=0.9`；
- 默认时区为 `Asia/Singapore`，每个账号可以单独覆盖；
- 中国大陆、香港、澳门和台湾时区会被拒绝。

请求头或正文里原本没有这些字段时，插件不会凭空添加。

## 当前链路

打票必须返回 `780`，并同时具有会话 ID、Cookie 和完整的 `__cflb/__oailb` 路由对。插件保存的是业务出口复验返回的新票，不是最初采集到的那张票。`allow` 只允许列表内网关，`deny` 只拒绝列表内网关，`any` 不限制网关；三种策略都要求路由 Cookie 完整。

推荐参数：

| 参数 | 建议 |
| --- | --- |
| 票据持续期 | `240` 秒起 |
| 网关策略 | 优先 `allow`；排除特定坏网关时用 `deny` |
| 网关列表 | `unified-15,unified-88,unified-180` |
| 复用上一轮网关 Cookie 打票 | 开启 |
| 打票指纹收敛为 codex-tui | 开启 |
| 并发打票数 | `3`；如果额度或生成器压力较大，可改为 `2` |
| 备用票 | 开启 |
| 备用票提前时间 | `90` 秒 |
| 优先使用上一轮出票 IP | 开启 |

## 票据如何变为可用

插件不会把刚返回的 STATE 直接投入业务。一次成功获取必须依次完成：

1. 获取或复用生成出口，并检查出口地区。
2. 发起打票请求，确认 STATE 长度和实际模型。
3. 在业务出口上携带该 STATE 再复验一次。
4. 启用质量探针时再执行一次提示词问答。
5. `strict` 只有答案命中才发布；`strict_fallback` 没有旧票时允许发布明确标注的临时票。
6. 严格合格票找到后会替换临时票；持久化失败不会替换当前可用票据。

续期、备用票获取和临时票后台升级期间，当前仍可用的旧票继续服务。并发打票共享“每轮最多尝试”总预算，严格合格票提交后会取消其他请求。

## 4.7.0 最新模式

- 正式配置只保留 Cookie + `780`，旧 `ticket_mode=legacy` 和 `allow_state_780=false` 保存时自动迁移；
- 删除配置页里的运行方式、独立 780 开关、旧 292/332 有效期和账号级旧出口配置；
- 质量探针改为 `strict_fallback / strict / off` 三态；
- `strict_fallback` 没有旧票时会发布“可用 · 未通过质量”的临时票保活，并在后台按常规重试间隔继续寻找严格合格票；
- 找到严格合格票后会直接替换临时票，不再等待临时票接近过期；
- 新增 `mint_concurrency=1..3`，默认 `3` 路并发完成生成器、出口检查和打票；
- 并发工作共享 `max_attempts` 总预算，严格合格票提交后取消其他打票请求；
- 票据持续期在配置页只保留一个入口，同时写入 Cookie 和 780 的有效期字段，避免两个数值互相覆盖。

## 4.6.1 诊断面板修复

- 诊断日志改为宿主内全屏独立工作区，只有一个纵向滚动区，不再使用可拖动窗口、横向表格或嵌套滚动条；
- 事件明细改为纵向卡片，在中小屏和大窗口中都可以直接阅读，不需要寻找底部的横向拉条；
- 删除混合口径的“出现、通过、通过率”统计，改为按网关显示采集成功、复验通过、质量通过、质量未通过和其他失败；
- 面板明确说明同一张票会经过多个阶段，各阶段计数不能相加为总通过率；
- 质量探针结果本地化为“质量通过 / 质量未通过”，并说明返回新 `780` 不代表降智，探针答案命中才是发布门槛；
- 本修复不改变打票、复验、质量探针、备用票或网关判定逻辑。

## 4.6.0 新增内容

- 配置页新增“启用票据质量探针（可消耗额度）”，默认关闭；
- 可填写一条提示词和最多 `8` 个逗号分隔的通过答案，答案按不区分大小写的包含关系匹配；
- 新票通过原有同出口复验后，再发起一次质量请求；命中通过答案才发布新票；
- 未命中记录 `quality_mismatch`，继续重新打票，当前仍有效的旧票不会被替换；
- 质量请求返回的新 STATE 和 Cookie 会在通过网关与会话完整性检查后滚动保存；
- 返回 `312`、错误模型、错误网关、会话不完整或探针请求失败时均不会发布候选票；
- 关闭“打票指纹收敛”时，质量探针不会再被旧逻辑强制成“只回复 pong”；
- 质量探针会消耗一次上游额度，仓库默认关闭，是否开启由账号持有人决定。

本轮 `80` 个独立出口的对比没有找到可长期复用的静态白名单：`17` 在 `unified-160`、`165`、`193`、`198` 等多个网关都出现过，固定出口和固定 Cookie 也不能保证持续命中。质量探针因此只做“新票发布前验收”，不承诺永久不降智。

## 4.5.2 修复内容

- `780` 票据必须同时携带非空 `__cflb` 和 `__oailb`，缺少任一项都返回 `gateway_unavailable` 并快速重打；
- 网关策略为 `any` 时仍执行路由 Cookie 完整性检查，`any` 只取消网关白/黑名单判断；
- 备用票恢复、内存票据恢复和打票完成后持久化前使用同一完整性规则，避免绕过入口不一致；
- 增加分别缺少 `__cflb`、缺少 `__oailb` 的规则测试和引擎测试。

## 4.5.1 新增内容

- 网关策略新增 `allow / deny / any` 三态；旧配置会自动迁移，原白名单默认迁移为 `allow`，原来的 `any` 或空列表迁移为 `any`；
- `allow` 只允许列表内网关，`deny` 只拒绝列表内网关，`any` 不限制网关；`allow/deny` 在 `4.5.1` 已要求完整的 `__cflb/__oailb`，`any` 的完整性缺口由 `4.5.2` 修复；
- 默认候选为 `unified-15,unified-88,unified-180`，不再把 `unified-88` 当成唯一正确网关；
- 复用上一轮 Cookie 时，只复用仍然符合当前策略且未过期的路由对；
- 实时诊断窗口在 `4.5.1` 曾使用标题栏拖动和表格独立滚动；`4.6.1` 已替换为全屏单滚动事件面板；
- 诊断事件常驻插件内存，只保留最近 5 小时并设置 5000 条硬上限，插件重启后清空；面板最多读取最新 2000 条，关闭面板不再清除历史；
- 诊断面板新增网关分布统计；`4.6.1` 起改为按处理阶段计数，不再显示混合口径的通过率；
- 同一网关可能同时出现正常和降智样本，因此网关号只能作为筛选证据，不能单独证明不降智。

## 4.4.0 新增内容

- `780` 不再只按长度识别，改为读取 Fernet 兼容 STATE 内的签发时间，默认持续期 `240` 秒；
- 新增“目标网关（780）”，默认 `unified-88`；没有 `__cflb/__oailb` 路由对、网关无法识别或落到其他网关时快速重打；
- 新增“复用上一轮网关 Cookie 打票”，只复用同一账号、未过期且命中目标网关的路由对；
- 新增“打票指纹收敛为 codex-tui”，统一 User-Agent、originator、低推理参数、工具参数和输入结构；
- `780` 进入业务链路时注入绑定会话的 `session_id` 与 Cookie，并兼容 `session-id` 命名；
- 业务响应中的新 `780` 和 Cookie 继续滚动更新，但网关不匹配时不会覆盖当前票据；
- 诊断新增票龄、STATE 指纹、Cookie 指纹、目标网关和会话绑定状态，不输出原始票据或 Cookie。

## 4.3.2 新增内容

- 新增“兼容新版 780 状态（实验）”开关，默认关闭；
- 业务出口复验返回新的 `780` 时，保存复验返回的新票，不再错误地保留采集阶段的旧票；
- Cookie 模式合并复验和业务响应中的新 Cookie，持续刷新 `__cf_bm`；
- 同一 `session_id` 下允许 `292` 与 `780` 按上游响应滚动切换；
- `780` 仍必须通过业务出口复验，收到 `312`、模型不一致或请求失败时丢弃。

## 4.3.3 修复内容

- 实时诊断改用三次并行状态信号建立监听，不再因单次宿主响应较慢而错过监听窗口；
- 诊断面板正确显示 `780` 票据类别；
- 监听失败时面板直接显示宿主错误，不再长期停留在“正在建立实时监听…”；
- 收到 `780` 后仍需触发一次实际模型请求或等待续期，监听面板才会出现新事件。

## 4.3.1 修复内容

- 删除官方 Sub2API `v0.2.8` 不支持的 `proxies.list`、`accounts.list` Bridge 调用；
- 配置页不再等待 20 秒后提示“无法读取 IP 管理代理列表”；
- 第一层代理改为直接粘贴 `http`、`https`、`socks5` 或 `socks5h` 完整地址；
- 已发现账号下拉只显示账号 ID，名称、邮箱、到期时间和额度可在添加后填写；
- 保存时统一写入 `upstream_proxy_id: 0`，后端实际使用 `upstream_proxy_url`，代理链行为不变。

## 4.3.0 新增内容

- 同步官方 Sub2API `v0.2.8` 的 HostService v2 契约；
- 根据宿主返回的 `schedulable` 跳过暂停、限流、过载或额度不可调度的账号；
- 新增全局请求环境替换开关、默认时区和账号级时区；
- 保留 `v4.2.1` 的 Cookie 分流、备用票、生成器复用和地区过滤逻辑。

## 4.2.1 续期优化

- 将出口 IP 与地区检查合并为一次请求。
- 同一出口的复验只复核 IP 是否变化，不再重复查询地区。
- 地区被拦截、312、STATE 长度不符或复验失败时缩短重试等待。
- 旧模式也可提前准备备用票，优先复用当前正在工作的生成出口，失败后自动换新出口。
- 诊断耗时现在覆盖代理生成、出口检查和探测，便于继续调整提前量。

这些历史优化不降低复验标准；`4.7.0` 已不再维护 292 运行模式。上游会话、出口质量和账号状态仍会决定最终成功率。

## B2Proxy 提取设置

注册入口：[B2Proxy](https://www.b2proxy.com/signup?code=FF10AB)

| 选项 | 设置 |
| --- | --- |
| 国家和地区 | `GLOBAL` |
| 提取数量 | `1` |
| 协议 | `HTTP/HTTPS` |
| 数据格式 | `TXT` |
| 会话类型 | `黏性IP` |
| IP 时长 | `180` 分钟 |
| 提前更换 IP | `否` |

生成器地址保留：

```text
proto=http&stype=txt&sessType=sticky&sessTime=180&sessAuto=0
```

不要使用 `sessAuto=1`。它可能在会话中途更换出口。

## 安装

Linux amd64 主机优先下载专用包：

```text
sub2api-state-kit_plugin_v4.7.0_linux_amd64.s2plugin
```

需要在多个平台间复用时下载通用包：

```text
sub2api-state-kit_plugin_v4.7.0.s2plugin
```

`linux_amd64` 专用包只包含当前平台 runtime，体积更小；通用包包含 Linux amd64、Linux arm64 和 macOS arm64 runtime。首次安装先把 Release 中的 `trusted-publisher.yaml` 合并到宿主现有 `config.yaml`，重启一次 Sub2API，再上传 `.s2plugin`。已安装旧版时可以直接升级，配置会保留。

完整说明见 [插件安装与使用指南](docs/plugin.md)，探测和验证边界见 [插件验证记录](docs/plugin-validation.md)。
