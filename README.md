# Sub2API STATE Kit 插件

本仓库只维护 Sub2API `v0.2.7` 的独立 `.s2plugin` 插件，不覆盖宿主源码。`4.2.0` 提供两种票据模式：

- **旧模式**：第一层代理 -> 代理生成器 -> 同一个粘性出口负责打票、复验和业务请求。
- **Cookie 分流模式**：打票出口和业务出口可以分开，通过 `state + Cookie + session_id` 保持同一会话。

两种模式都会拒绝香港 `HK` 和无法确认地区的出口。插件不会把 OAuth Token、Cookie、STATE 或代理凭据写入诊断日志。

## 开关说明

### 总开关

`启用 STATE Kit` 控制插件是否获取和注入票据。关闭后停止后台采集，正常请求继续由宿主转发。

### 票据模式

`旧模式` 要求采集、复验和业务请求使用同一个粘性出口。历史上同一张 292 换到第一层出口后会立刻变成 312，因此旧模式仍保留“打票出口与用票出口一致”的检查。

`Cookie 分流模式` 在打票时保存响应中的 Cookie 和 `session_id`，业务请求通过独立业务出口携带这些信息。跨出口成功已有连续 `4/4` 次实测，但样本仍有限，开启前应先用实际模型请求验收。

### Cookie 模式打票方式

`代理生成器 API`：插件调用生成器获取粘性出口，可配合“优先使用上一轮出票 IP”。适合 B2Proxy 这类按 API 生成 `host:port` 的服务。

`S5/HTTP 固定采集代理`：直接使用填写的采集代理打票。支持 `http`、`https`、`socks5`、`socks5h`；配置第一层时链路为“第一层 -> 采集代理 -> ChatGPT”。

### 第一层代理

旧模式下，第一层代理只负责访问生成器，生成出的第二层代理才是业务出口。Cookie 模式下，如果没有单独填写业务固定代理，业务请求使用第一层代理作为出口。

### Cookie 模式采集代理

仅在选择 `S5/HTTP 固定采集代理` 时必填。它决定 Cookie 会话从哪里取得，不要求与业务出口相同。

### Cookie 模式业务固定代理

业务请求实际使用的出口，可留空使用第一层代理。这里不再要求与采集出口相同，但仍会拒绝香港和未知地区。

### Cookie 票据持续期

单位为秒，默认 `300`。实测新的 292 约持续 `1.13` 到 `6.05` 分钟，所以默认按约 5 分钟管理。该值是插件认为票据可继续复用的本地时限，不是上游承诺。

### 备用票队列

开启后，当前票据剩余时间低于“备用票提前量”时，后台会获取并完整复验一张备用票；当前票失效、收到 312 或模型不符时，备用票才自动晋级。备用票只保留一张，不会因为正在采集新票而中断当前可用票。

### 备用票提前量

默认 `90` 秒，必须小于 Cookie 票据持续期。想减少当前票失效时的等待，可以设置为略大于一次完整采集、复验所需时间；设置过大会增加代理调用频率。

### 优先使用上一轮出票 IP

开启后，每个账号先复用上次复验通过的生成器出口，失败才向生成器获取新出口。该开关只影响代理生成器模式，不影响固定 S5/HTTP 采集代理。

### 生成器阻止国家和地区

默认保留 `HK`。可以追加其他 ISO 两位代码，例如 `HK, CN`；未知地区同样拒绝并重新获取。

## B2Proxy 配置

通过 [B2Proxy 注册入口](https://www.b2proxy.com/signup?code=FF10AB) 登录后创建提取链接：

| 选项 | 设置 |
| --- | --- |
| 国家和地区 | `GLOBAL` |
| 提取数量 | `1` |
| 代理协议 | `HTTP/HTTPS` |
| 数据格式 | `TXT` |
| 会话类型 | `黏性IP` |
| IP 时长 | `180` 分钟 |
| 提前更换 IP | `否` |

生成器地址必须保留 `sessType=sticky&sessTime=180&sessAuto=0`。`sessTime=180` 是代理会话上限，不表示单张 292 一定能持续 180 分钟。

## 推荐配置

旧模式保持兼容：

| 配置项 | 建议 |
| --- | --- |
| 票据模式 | 旧模式 |
| 第一层代理 | 选择可访问生成器的固定代理 |
| 代理生成器 API | 粘贴完整 `.../gen?...` 地址 |
| 生成器阻止地区 | `HK` |
| 优先使用上一轮出票 IP | 开启 |
| 票据有效期 | `180` 分钟 |
| 提前续期 | `120` 秒 |
| 生成器出口有效期 | `180` 分钟 |

Cookie 分流模式：

| 配置项 | 建议 |
| --- | --- |
| 票据模式 | Cookie 分流模式 |
| 打票方式 | 代理生成器 API，或已验证的 S5/HTTP 固定采集代理 |
| 业务固定代理 | 留空使用第一层；也可填写独立固定出口 |
| 生成器阻止地区 | `HK` |
| Cookie 票据持续期 | `300` 秒 |
| 备用票队列 | 开启 |
| 备用票提前量 | `90` 秒 |
| 优先使用上一轮出票 IP | 开启 |

## 安装

Linux AMD64 宿主下载：

```text
sub2api-state-kit_plugin_v4.2.0_linux-amd64.s2plugin
```

首次安装先合并 Release 中的 `trusted-publisher.yaml` 到宿主现有 `config.yaml`，重启一次 Sub2API，再上传同架构 `.s2plugin`。已安装旧版时可直接升级，配置会保留。

完整说明见 [插件安装与使用指南](docs/plugin.md)，验证范围见 [插件验证记录](docs/plugin-validation.md)。

插件不包含账号、代理凭据、API Key、STATE、数据库或签名私钥。上游 Overload、429 和模型策略变化仍可能影响可用性。
