# STATE Kit 插件使用指南

适用于独立插件 `4.5.2` 和官方 Sub2API `v0.2.8`。插件不修改宿主源码，安装包为 `.s2plugin`。

## 1. 先选运行方式

### 稳定同出口（推荐）

打票、复验和业务请求始终使用同一个生成粘性出口。适合已验证的 180 分钟粘性 IP，也是历史 292 方案。

### Cookie 分流

打票和业务可以使用不同出口。打票响应必须同时提供：

- 长度符合套餐的 STATE；
- 非空 `session_id`；
- 至少一个响应 Cookie。

如果上游只返回 `780` 而不是 `292/332`，打开“兼容新版 780 状态（实验）”。新票必须同时具备会话 ID、Cookie，以及完整的 `__cflb/__oailb` 路由对；缺少任一路由 Cookie 都会拒票重打。`any` 只关闭网关白/黑名单判断，不会跳过这项完整性检查。成功样本中业务响应会同时返回新的 `780` 和 `__cf_bm`，插件会滚动覆盖当前票据。跨出口带 Cookie 已有连续成功样本，但仍应对自己的账号做实际模型请求验收。

## 2. 页面填写规则

第一层 S5/HTTP 代理地址由用户直接填写，两种方式共用：

- 代理生成器方式下，用于访问生成器 API；
- Cookie 分流的业务固定代理留空时，也作为业务出口；
- 固定 S5/HTTP 采集代理方式下，可作为前置代理。

直接填写完整的 `http`、`https`、`socks5` 或 `socks5h` 地址。官方 Sub2API `v0.2.8` 插件页不提供“IP 管理代理列表”，`4.3.1` 已移除对不存在的 `proxies.list`、`accounts.list` Bridge 方法的调用，不会再等待 20 秒后报读取失败。

### 请求环境统一

“统一请求环境日期、时区与语言”默认关闭。打开后，插件只修改请求里已经存在的字段：

- `<environment_context>` 内的 `<current_date>` 和 `<timezone>`；
- `type=user_location` 的 `timezone`；
- 已有的 `Accept-Language`，统一为 `en-US,en;q=0.9`。

默认请求时区是 `Asia/Singapore`。每个账号可在“账号资料”的“时区”栏覆盖。中国大陆、香港、澳门和台湾时区会被拒绝。该功能不添加原请求不存在的字段。

稳定同出口需要：

| 字段 | 填写 |
| --- | --- |
| 第一层 | 可访问生成器的完整 S5/HTTP 代理地址 |
| 代理生成器 API | B2Proxy 完整 `.../gen?...` 地址 |
| 账号出口方式 | 代理生成器 |
| 禁止出口地区 | `HK` |
| 优先使用上一轮出票 IP | 建议开启 |
| 提前准备备用票 | 建议开启 |

Cookie 分流需要：

| 字段 | 填写 |
| --- | --- |
| 第一层 | 与稳定模式相同的完整代理地址 |
| 打票方式 | 代理生成器 API，或已验证的 S5/HTTP 固定采集代理 |
| Cookie 模式采集代理 | 生成器方式留空；固定采集代理方式必填 |
| Cookie 模式业务固定代理 | 留空使用第一层，也可填写独立出口 |
| Cookie 票据持续期 | 建议 `300` 秒 |
| 兼容新版 780 状态 | 上游只返回 `780` 时开启；可取得 `292/332` 时保持关闭 |
| 780 票据持续期 | `240` 秒；以 Fernet 内嵌签发时间为起点 |
| 网关策略 | `allow` 只允许列表内网关；`deny` 只拒绝列表内网关；`any` 不限制网关 |
| 网关列表 | `allow/deny` 时填写，例如 `15,88,180` 或 `unified-15,unified-88,unified-180` |
| 复用上一轮网关 Cookie | 开启；仅复用符合当前策略且未过期的路由对 |
| 打票指纹收敛 | 开启；统一为参考实现验证过的 `codex-tui` 形态 |

## 3. B2Proxy 提取设置

注册入口：[https://www.b2proxy.com/signup?code=FF10AB](https://www.b2proxy.com/signup?code=FF10AB)

| 选项 | 设置 |
| --- | --- |
| 国家和地区 | `GLOBAL` |
| 提取数量 | `1` |
| 代理协议 | `HTTP/HTTPS` |
| 数据格式 | `TXT` |
| 分隔符 | `\r\n` |
| 会话类型 | `黏性IP` |
| IP 时长 | `180` 分钟 |
| 提前更换 IP | `否` |
| 代理主机 | `主机:端口` |

生成器地址必须保留：

```text
proto=http&stype=txt&sessType=sticky&sessTime=180&sessAuto=0
```

`sessTime=180` 是代理会话上限，不表示单张 292 一定能持续 180 分钟。不要使用 `sessAuto=1`。

## 4. 安装

1. 从 Release 下载 `trusted-publisher.yaml`，把其中公钥合并到宿主现有 `config.yaml`，不要覆盖原配置。
2. 重启一次 Sub2API，使公钥生效。
3. 在“插件管理”上传 `sub2api-state-kit_plugin_v4.5.2_linux_amd64.s2plugin`（Linux amd64 专用，体积更小）或 `sub2api-state-kit_plugin_v4.5.2.s2plugin`（包含 Linux amd64、Linux arm64 和 macOS arm64 runtime）。
4. 确认插件已签名、受信任、已启用，灰度 `100%`。
5. 同类 OpenAI OAuth transport 插件只启用一个。

## 5. 票据什么时候可用

新票据必须完成以下步骤才会替换当前票据：

1. 获取或复用生成出口，并检查地区。
2. 发起打票请求，校验 STATE 长度和响应模型。
3. 在业务出口上携带 STATE 再复验一次。
4. 复验成功时，如果响应带回新的 STATE，则保存新票；同时合并响应更新或删除的 Cookie。
5. 持久化成功后，票据进入“可用”。

刚取得 STATE 就立即使用会跳过第 3 步，把潜在 312 或模型错误暴露给业务请求，因此默认不这样做。

续期、备用票获取和复验期间，当前仍有效的旧票继续服务。备用票只保留一张，验证成功前不会替换当前票。

`780` 兼容模式遵循同样的复验规则，并保存复验响应中的滚动票。默认策略为 `allow`，列表为 `unified-15,unified-88,unified-180`。`deny` 只拒绝列表内网关，其他网关继续复验；`any` 只关闭网关白/黑名单判断，三种策略都仍要求完整的 `__cflb/__oailb` 路由对。缺少任一路由 Cookie、网关无法识别、网关被策略拒绝、返回 `312`、模型不一致或会话 Cookie 不完整时都不会替换当前票据。诊断面板会汇总各网关的出现、通过、拒绝、模型不符和通过率，便于根据实际线路调整策略。它与固定 `292` 不是互斥格式：在同一个 `session_id` 下，上游返回哪种合法长度，插件就保存哪种。

## 6. 速度与参数

`4.5.2` 在诊断监听和 `780` 滚动兼容之上增加目标网关验收：

- 第一层代理直接填写，不再调用不存在的 IP 管理代理列表和账号列表 Bridge；
- 已发现账号下拉只提供 ID，账号资料可在添加后填写；
- 实时诊断并行发送三次状态信号，宿主响应较慢时也能进入监听状态；
- 诊断面板显示 `780` 类别，监听失败时直接显示错误；
- 诊断窗口固定为大尺寸，标题栏可拖动，表格与网关统计区独立滚动；
- 诊断事件只保留最近 5 小时且最多 5000 条，面板最多显示最新 2000 条；关闭面板后历史仍可再次查看，插件重启后清空；
- `780` 默认拒绝，只有显式打开实验开关后才进入复验；
- `780` 按 Fernet 内嵌签发时间计算 `240` 秒窗口，不复用旧票剩余时间；
- `allow` 默认只接受 `unified-15,unified-88,unified-180`，并复用同一账号上一轮仍符合策略的目标网关 Cookie；
- `allow / deny / any` 都要求完整的 `__cflb/__oailb` 路由对，缺少任一项都会拒票重打；
- 诊断面板汇总每个网关的出现、通过、模型不符、拒绝次数和通过率；
- 打票请求默认收敛为参考实现验证过的 `codex-tui` 请求形态；
- 复验返回的新票和新 Cookie 仅在目标网关一致时覆盖当前票据；
- IP 与地区查询合并；
- 业务出口复验只复核配置要求的出口关系，不重复查询地区；
- 地区被拦截、312、STATE 长度不符和复验失败会自动快速重试；
- 旧模式备用票优先复用当前生成出口，失败后自动获取新出口；
- 诊断耗时覆盖生成器、出口检查和探测。

建议：

| 参数 | 建议 |
| --- | --- |
| 旧模式票据有效期 | `180` 分钟 |
| 旧模式提前续期 | `120` 秒起；续期经常失败时改为 `300` 秒 |
| 生成器出口有效期 | `180` 分钟 |
| 每轮最多尝试 | `8` |
| 常规重试间隔 | `10` 秒 |
| 失败后冷却 | `300` 秒 |
| 备用票提前时间 | `90` 秒起，应大于一次完整获取耗时 |

实际提前量应根据诊断里的生成器耗时、采集耗时和复验耗时调整，不要只增加固定猜测值。

## 7. 验证

1. 保存配置，等待状态显示“可用”。
2. 打开“查看诊断日志”；面板会显示最近 5 小时的仅内存事件，可拖动标题栏移动，关闭后不会清空。
3. 发起一次实际模型请求，确认返回目标模型。
4. 检查诊断中的生成出口、业务出口、STATE 类别、目标网关、票龄、会话绑定、响应模型和耗时。
5. 让当前票接近失效或收到 312，确认备用票可自动顶替。

“检查已保存配置”只检查配置和宿主账号绑定，不发模型请求，也不探测代理。

## 8. 常见问题

- 生成器不可用：检查生成器地址和第一层是否能访问该域名。
- 地区被阻止：出口落在 `HK` 或地区查询失败，插件会重新获取。
- Cookie 票据无效：确认响应同时有 STATE、`session_id` 和 Cookie。
- 只能拿到 `780`：打开“兼容新版 780 状态（实验）”，并检查诊断里复验是否返回 `312` 或错误模型。
- 票据会变化但服务不断：这是预期的滚动更新。成功样本中 `780` 和 `__cf_bm` 会在每次有效响应后更换。
- 备用票不出现：确认开关和提前时间正确，并查看诊断错误。
- 292 仍变化：代理出口不变也可能发生，这是上游会话生命周期变化。
- 升级：直接上传新版 `.s2plugin`，配置会保留。

插件不会保存 OAuth Token、Cookie、STATE、代理凭据、API Key 或签名私钥到诊断日志。诊断历史只存在当前插件进程内，最迟 5 小时后自动删除，插件重启也会清空。
