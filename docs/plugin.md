# STATE Kit 插件使用指南

适用于独立插件 `4.7.0` 和官方 Sub2API `v0.2.8`。插件不修改宿主源码，安装包为 `.s2plugin`。

## 1. 当前票据模式

插件只维护 Cookie + `780`。正式配置不能启用 292/332，旧配置保存时自动迁移。香港和未知出口始终拒绝。

打票响应必须同时提供：

- `780` STATE；
- 非空 `session_id`；
- 响应 Cookie；
- 完整的 `__cflb/__oailb` 路由对。

缺少任一项都会拒票重打。`allow` 只允许列表内网关，`deny` 只拒绝列表内网关，`any` 不限制网关；三种策略都要求完整路由对。

质量探针有三种模式：

| 模式 | 行为 |
| --- | --- |
| `strict_fallback` | 严格合格票优先；没有旧票时先发布临时票保活，后台继续寻找严格票 |
| `strict` | 只发布回答命中的票 |
| `off` | 不执行质量问答 |

临时票在状态页明确显示“临时票 · 未通过质量”。严格合格票找到后会直接替换临时票，不会伪装成严格合格票。

## 2. 页面填写规则

第一层 S5/HTTP 代理地址由用户直接填写，用于访问代理生成器。打票方式可选：

- 代理生成器 API：每次取得一个粘性出口，推荐保留 `sessTime=180&sessAuto=0`；
- S5/HTTP 固定采集代理：直接使用固定采集代理打票。

业务固定代理留空时使用第一层，也可以填写独立出口。支持完整的 `http`、`https`、`socks5` 或 `socks5h` 地址。账号级不再提供旧出口方式，账号只需选择开关、Pro/Team 和模型。

### 请求环境统一

“统一请求环境日期、时区与语言”默认关闭。打开后，插件只修改请求里已经存在的字段：

- `<environment_context>` 内的 `<current_date>` 和 `<timezone>`；
- `type=user_location` 的 `timezone`；
- 已有的 `Accept-Language`，统一为 `en-US,en;q=0.9`。

默认请求时区是 `Asia/Singapore`。每个账号可在“账号资料”的“时区”栏覆盖。中国大陆、香港、澳门和台湾时区会被拒绝。该功能不添加原请求不存在的字段。

### 票据质量探针

质量探针用于把“模型回答是否符合预期”纳入新票验收。选择 `strict` 或 `strict_fallback` 后：

1. 新票先完成原有打票、同出口复验、STATE 与网关检查；
2. 插件再携带同一会话发起一次质量提示词；
3. 回复不区分大小写包含任意一个“通过答案”时，发布严格合格票；
4. `strict` 未命中时丢弃候选并继续重打；
5. `strict_fallback` 没有旧票时允许发布临时票保活，并按常规重试间隔继续寻找严格票；
6. 质量请求返回的新 STATE 和 Cookie 会在检查通过后滚动保存。

例如提示词填写“不要联网，不要猜测，说出你知道的最新苹果手机”，通过答案填写 `17`，可以接受 `iPhone 17` 这类包含 `17` 的回复。最多填写 `8` 个通过答案，每个最多 `64` 个字符。

质量探针会额外消耗一次上游额度。`80` 个独立出口的对比未找到可长期维持的固定网关、出口、Cookie 或响应头白名单，因此质量探针是“发布前验收”，不是永久不降智保证。提示词会发送给上游，不要填写密码、Token 或其他敏感信息。

推荐填写：

| 字段 | 填写 |
| --- | --- |
| 第一层 | 可访问生成器的完整 S5/HTTP 代理地址 |
| 打票方式 | 代理生成器 API，或已验证的 S5/HTTP 固定采集代理 |
| 打票采集代理 | 生成器方式留空；固定采集代理方式必填 |
| 业务固定代理 | 留空使用第一层，也可填写独立出口 |
| 票据持续期 | 建议 `240` 秒起 |
| 网关策略 | `allow` 只允许列表内网关；`deny` 只拒绝列表内网关；`any` 不限制网关 |
| 网关列表 | `allow/deny` 时填写，例如 `15,88,180` 或 `unified-15,unified-88,unified-180` |
| 复用上一轮网关 Cookie | 开启；仅复用符合当前策略且未过期的路由对 |
| 打票指纹收敛 | 开启；统一为参考实现验证过的 `codex-tui` 形态 |
| 并发打票数 | 默认 `3`；生成器或额度压力较大时可改为 `2` |

## 3. B2Proxy 提取设置

注册入口：[https://www.b2proxy.com/signup?code=FF10AB](https://www.b2proxy.com/signup?code=FF10AB)

| 选项 | 设置 |
| --- | --- |
| 国家和地区 | `GLOBAL` |
| 提取数量 | `1` |
| 代理协议 | `HTTP/HTTPS` |
| 数据格式 | `TXT` |
| 分隔符 | `\r\n` |
| 会话类型 | `黏性IP` |
| IP 时长 | `180` 分钟 |
| 提前更换 IP | `否` |
| 代理主机 | `主机:端口` |

生成器地址必须保留：

```text
proto=http&stype=txt&sessType=sticky&sessTime=180&sessAuto=0
```

`sessTime=180` 是代理会话上限，不表示单张 780 一定能持续 180 分钟。不要使用 `sessAuto=1`。

## 4. 安装

1. 从 Release 下载 `trusted-publisher.yaml`，把其中公钥合并到宿主现有 `config.yaml`，不要覆盖原配置。
2. 重启一次 Sub2API，使公钥生效。
3. 在“插件管理”上传 `sub2api-state-kit_plugin_v4.7.0_linux_amd64.s2plugin`（Linux amd64 专用，体积更小）或 `sub2api-state-kit_plugin_v4.7.0.s2plugin`（包含 Linux amd64、Linux arm64 和 macOS arm64 runtime）。
4. 确认插件已签名、受信任、已启用，灰度 `100%`。
5. 同类 OpenAI OAuth transport 插件只启用一个。

## 5. 票据什么时候可用

新票据必须完成以下步骤才会替换当前票据：

1. 获取或复用生成出口，并检查地区。
2. 发起打票请求，校验 STATE 长度和响应模型。
3. 在业务出口上携带 STATE 再复验一次。
4. 复验成功时，如果响应带回新的 STATE，则保存新票；同时合并响应更新或删除的 Cookie。
5. 如果启用质量探针，再执行一次可配置问答。
6. 严格模式只有答案命中才发布；严格优先模式没有旧票时可以发布临时票保活。
7. 严格合格票找到后会替换临时票，持久化成功后状态变为“可用”。

刚取得 STATE 就立即使用会跳过第 3 步，把潜在 312 或模型错误暴露给业务请求，因此默认不这样做。

续期、备用票获取和临时票后台升级期间，当前仍有效的旧票继续服务。备用票只保留一张，验证成功前不会替换当前票。并发打票共享“每轮最多尝试”总预算，严格合格票提交后取消其他打票请求。

`780` 遵循业务出口复验和滚动保存规则。默认策略为 `allow`，列表为 `unified-15,unified-88,unified-180`。`deny` 只拒绝列表内网关，其他网关继续复验；`any` 只关闭网关白/黑名单判断，三种策略都仍要求完整的 `__cflb/__oailb` 路由对。缺少任一路由 Cookie、网关无法识别、网关被策略拒绝、返回 `312`、模型不一致或会话 Cookie 不完整时都不会替换当前票据。诊断面板按网关记录采集、复验和质量探针的阶段结果；同一张票经过多个阶段，各计数不能相加成总通过率。

## 6. 速度与参数

### 4.7.0 最新模式

- 正式配置只维护 Cookie + `780`，旧 292/332 配置保存时自动迁移；
- 质量探针支持 `strict_fallback / strict / off`；
- `strict_fallback` 发布临时票后，会按“常规重试间隔”在后台继续寻找严格合格票；
- 严格合格票会直接替换临时票；
- 并发打票数支持 `1..3`，默认 `3`，多个 worker 共享“每轮最多尝试”总预算；
- 严格合格票提交后取消其他打票请求。

### 4.6.1 诊断面板

- “查看诊断日志”打开宿主内全屏工作区，只有事件区域一个纵向滚动条；
- 事件改为纵向卡片，代理链、出口 IP、票据状态、质量、响应、结果和耗时都可直接展开阅读；
- 网关统计按“采集成功、复验通过、质量通过、质量未通过、其他失败”分阶段显示；
- 不再使用“出现、通过、通过率”的混合统计，因为同一张票会在采集、复验和质量探针中重复出现；
- 质量通过表示探针答案命中所设值；返回新的 `780` 只表示会话滚动，不能据此判断降智；
- `strict` 探针未通过时继续重打；`strict_fallback` 无旧票时会先发布临时票保活。

`4.6.0` 在诊断监听、`780` 滚动兼容和目标网关验收之上增加可选质量探针：

- 质量探针默认关闭，需要提示词和至少一个通过答案才能启用；
- 质量探针失败不会替换当前可用旧票，诊断阶段显示为“质量探针”；
- 关闭“打票指纹收敛”时不会强制探针只回复 `pong`；
- 第一层代理直接填写，不再调用不存在的 IP 管理代理列表和账号列表 Bridge；
- 已发现账号下拉只提供 ID，账号资料可在添加后填写；
- 实时诊断并行发送三次状态信号，宿主响应较慢时也能进入监听状态；
- 诊断面板显示 `780` 类别，监听失败时直接显示错误；
- 诊断窗口在 `4.6.0` 固定为大尺寸；`4.6.1` 起改为全屏单滚动事件面板；
- 诊断事件只保留最近 5 小时且最多 5000 条，面板最多显示最新 2000 条；关闭面板后历史仍可再次查看，插件重启后清空；
- `780` 在 `4.3.2` 至 `4.6.1` 需要显式打开实验开关；`4.7.0` 起强制只使用 Cookie + `780`；
- `780` 按 Fernet 内嵌签发时间计算 `240` 秒窗口，不复用旧票剩余时间；
- `allow` 默认只接受 `unified-15,unified-88,unified-180`，并复用同一账号上一轮仍符合策略的目标网关 Cookie；
- `allow / deny / any` 都要求完整的 `__cflb/__oailb` 路由对，缺少任一项都会拒票重打；
- 诊断面板新增网关分布；`4.6.1` 起按处理阶段统计，不计算混合通过率；
- 打票请求默认收敛为参考实现验证过的 `codex-tui` 请求形态；
- 复验返回的新票和新 Cookie 仅在目标网关一致时覆盖当前票据；
- IP 与地区查询合并；
- 业务出口复验只复核配置要求的出口关系，不重复查询地区；
- 地区被拦截、312、STATE 长度不符和复验失败会自动快速重试；
- 历史上旧模式备用票优先复用当前生成出口；`4.7.0` 已移除旧模式；
- 诊断耗时覆盖生成器、出口检查和探测。

建议：

| 参数 | 建议 |
| --- | --- |
| 生成器出口有效期 | `180` 分钟 |
| 票据持续期 | `240` 秒起 |
| 每轮最多尝试 | `8` |
| 并发打票数 | `3` |
| 常规重试间隔 | `10` 秒 |
| 失败后冷却 | `300` 秒 |
| 备用票提前时间 | `90` 秒起，应大于一次完整获取耗时 |
| 质量探针 | 推荐 `strict_fallback`；提示词尽量短，答案使用稳定数字或短语 |

实际提前量应根据诊断里的生成器耗时、采集耗时和复验耗时调整，不要只增加固定猜测值。

## 7. 验证

1. 保存配置，等待状态显示“可用”。
2. 打开“查看诊断日志”；面板会显示最近 5 小时的仅内存事件，在一个全屏纵向滚动区中阅读，关闭后不会清空。
3. 发起一次实际模型请求，确认返回目标模型。
4. 检查诊断中的生成出口、业务出口、STATE 类别、目标网关、票龄、会话绑定、响应模型和耗时。
5. 如果启用 `strict_fallback`，允许先看到“临时票 · 未通过质量”，随后观察是否升级为“严格合格”。
6. 让当前票接近失效或收到 312，确认备用票可自动顶替。

“检查已保存配置”只检查配置和宿主账号绑定，不发模型请求，也不探测代理。

## 8. 常见问题

- 生成器不可用：检查生成器地址和第一层是否能访问该域名。
- 地区被阻止：出口落在 `HK` 或地区查询失败，插件会重新获取。
- Cookie 票据无效：确认响应同时有 STATE、`session_id` 和 Cookie。
- 只能拿到 `780`：这正是当前正式模式；检查诊断里复验是否返回 `312`、错误模型或路由 Cookie 不完整。
- 票据会变化但服务不断：这是预期的滚动更新。成功样本中 `780` 和 `__cf_bm` 会在每次有效响应后更换。
- 备用票不出现：确认开关和提前时间正确，并查看诊断错误。
- 质量探针一直不通过：可以临时选择 `off` 确认账号和模型可回复，或使用 `strict_fallback` 保持临时票服务；再检查提示词、通过答案和诊断中的 `quality_mismatch`。不要把固定网关、固定 IP 或固定 Cookie 当作永久不降智保证。
- 升级：直接上传新版 `.s2plugin`，配置会保留。

插件不会保存 OAuth Token、Cookie、STATE、代理凭据、API Key 或签名私钥到诊断日志。诊断历史只存在当前插件进程内，最迟 5 小时后自动删除，插件重启也会清空。
