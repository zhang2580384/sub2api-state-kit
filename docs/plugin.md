# STATE Kit 插件使用指南

本指南适用于独立插件版 `4.2.0` 和官方 Sub2API `v0.2.7`。插件不修改宿主源码，安装包为 `.s2plugin`。

## 1. 两种运行模式

### 旧模式：同出口绑定

链路：

```text
插件 -> 第一层代理 -> 代理生成器 API
插件 -> 第一层代理 -> 生成的粘性出口 -> ChatGPT
```

打票、固定出口复验和业务请求全部使用同一个生成出口。插件会拒绝采集出口与业务出口不一致的票据。该模式兼容原来的 180 分钟粘性 IP 方案。

### Cookie 分流模式

链路：

```text
打票：第一层 -> S5/HTTP 采集代理或生成器 -> ChatGPT
业务：第一层或业务固定代理 -> ChatGPT
会话：state + Cookie + session_id
```

打票响应中的完整 Cookie 和 `session_id` 会与 STATE 一起保存，业务请求在独立出口上重新携带同一会话。该模式不再强制打票与业务出口相同。跨出口带 Cookie 已有连续 `4/4` 次实测成功，但仍属于新方案，必须以自己的实际模型请求验收。

Cookie 模式下，三项缺少任意一项都不算完整票据：

- STATE 长度与套餐一致；
- `session_id` 非空；
- 至少有一个打票响应 Cookie。

## 2. 获取代理 API

使用 B2Proxy 注册入口：[https://www.b2proxy.com/signup?code=FF10AB](https://www.b2proxy.com/signup?code=FF10AB)

创建提取链接时按以下参数设置：

| 选项 | 设置 |
| --- | --- |
| 国家和地区 | `GLOBAL` |
| 提取数量 | `1` |
| 代理协议 | `HTTP/HTTPS` |
| 数据格式 | `TXT` |
| 分隔符 | `\r\n` |
| 会话类型 | `黏性IP` |
| IP 时长 | `180` 分钟 |
| 提前更换 IP | `否` |
| 代理主机 | `主机:端口` |

复制完整 `.../gen?...` 地址。必须保留：

```text
proto=http&stype=txt&sessType=sticky&sessTime=180&sessAuto=0
```

`sessTime=180` 是代理供应商的会话上限，不是上游 292 的持续时间承诺。不要使用 `sessAuto=1`，实测它可能在约 18.7 分钟时提前切换出口。

## 3. 配置第一层代理

旧模式必须配置第一层代理，插件通过它调用生成器，再连接生成出的第二层粘性出口。

Cookie 模式可以选择：

- 生成器打票：仍需要第一层访问生成器；
- S5/HTTP 固定采集代理：如果没有第一层，插件直接连接采集代理；如果填写第一层，链路为“第一层 -> 采集代理 -> ChatGPT”；
- 业务出口：留空时使用第一层；也可以配置独立的业务固定代理。

第一层、采集代理和业务代理支持 `http`、`https`、`socks5`、`socks5h`。

## 4. 安装插件

1. 从 Release 下载 `trusted-publisher.yaml`，把其中 `state-kit-local-v1` 公钥合并到 Sub2API 现有 `config.yaml`。不要覆盖原配置。
2. 重启一次 Sub2API 应用服务，使公钥生效。
3. 在 **插件管理** 上传 `sub2api-state-kit_plugin_v4.2.0_linux-amd64.s2plugin`。ARM64 宿主使用对应 ARM64 包。
4. 确认文件处于已签名、受信任和已启用状态，灰度设为 `100%`。
5. 如果启用了其他同类 OpenAI OAuth transport 插件，先停用它们；同类 transport 只启用一个。

## 5. 控制开关说明

### 启用 STATE Kit

总开关。关闭后不获取、不注入票据；正常业务请求继续按宿主原有方式转发。

### 票据模式

`旧模式`：同出口绑定。兼容原有 180 分钟粘性 IP 流程。

`Cookie 分流模式`：启用 Cookie 会话和可选备用票队列，允许打票、业务出口分离。

### Cookie 模式打票方式

`代理生成器 API`：每次可获取一个粘性出口。适合 B2Proxy，可配合上一轮出票 IP 复用。

`S5/HTTP 固定采集代理`：直接使用固定采集链路。该选项不参与上一轮生成器 IP 复用。

### 代理生成器 API

填写完整 `.../gen?...` 地址。旧模式下生成出口同时用于打票和业务；Cookie 模式下生成出口只用于打票、复验，业务出口按业务固定代理或第一层计算。

### Cookie 模式采集代理

选择 `S5/HTTP 固定采集代理` 时必填。打票阶段携带 `state + Cookie + session_id`，但新增或更新票据时不会沿用调用方旧 Cookie。

### Cookie 模式业务固定代理

业务请求出口。留空使用第一层；填写后使用该固定代理。插件会探测业务出口并拒绝 `HK` 和未知地区。

### Cookie 票据持续期

默认 `300` 秒，范围 `30` 到 `1800` 秒。实测 292 常见持续时间为 `1.13` 到 `6.05` 分钟，因此按约 5 分钟管理更接近当前上游行为。

该值是插件的本地复用时限。即使设置为 10 分钟或更大，上游也可能提前返回 312 或错误模型。

### 备用票队列

开启后，当前票剩余时间低于提前量时，后台采集并完整复验一张备用票。备用票验证成功前不会替换当前票；当前票失效、收到 312 或模型不符时，备用票自动晋级。

备用票只保留一张。晋级前会核对：

- 账号和模型；
- 业务出口指纹；
- 账号身份指纹；
- STATE 套餐长度、`session_id` 和 Cookie 完整性。

### 备用票提前量

默认 `90` 秒，必须小于 Cookie 票据持续期。该值应大于一次完整采集和复验耗时，否则备用票可能来不及准备好；设置过大会更频繁调用采集代理。

### 优先使用上一轮出票 IP

开启后，每个账号先尝试上次通过复验的生成器出口；复用失败才重新调用生成器。旧模式下仍要求该出口与业务出口一致；Cookie 模式下会重新验证 Cookie 会话。

### 生成器阻止国家和地区

默认 `HK`。请输入 ISO 两位代码，逗号分隔。香港始终建议保留；无法确认国家的 IP 也会被拒绝。

### 旧模式高级参数

`票据有效期` 和 `提前续期` 只用于旧模式。默认有效期 `180` 分钟、提前续期 `120` 秒。续期过程中旧票继续服务。

`生成器出口有效期` 表示打票链路准备的代理会话上限，仍不超过 `180` 分钟。它不是上游 292 的硬保证。

## 6. 推荐设置

### 旧模式

| 配置项 | 建议值 |
| --- | --- |
| 第一层代理 | 已添加的固定 HTTP(S) 或 SOCKS5(h) 代理 |
| 代理生成器 API | B2Proxy 完整提取链接 |
| 阻止国家或地区 | `HK` |
| 优先使用上一轮出票 IP | 开启 |
| 票据有效期 | `180` 分钟 |
| 提前续期 | `120` 秒 |
| 生成器出口有效期 | `180` 分钟 |
| 每轮最多尝试 | `8` |
| 尝试间隔 | `10` 秒 |
| 失败后冷却 | `300` 秒 |

账号出口模式选择 `代理生成器`，套餐选择 `Pro（292）` 或 `Team（332）`，模型填写实际使用的 `gpt-*`。

### Cookie 分流模式

| 配置项 | 建议值 |
| --- | --- |
| 打票方式 | 代理生成器 API，或已验证的 S5/HTTP 固定采集代理 |
| 业务固定代理 | 留空使用第一层；也可填写独立固定出口 |
| 阻止国家或地区 | `HK` |
| Cookie 票据持续期 | `300` 秒 |
| 备用票队列 | 开启 |
| 备用票提前量 | `90` 秒 |
| 优先使用上一轮出票 IP | 开启 |

## 7. 如何验证

1. 保存配置后等待状态显示“可用”。
2. 确认状态包含票据模式、剩余时间和备用票剩余时间。
3. 打开实时诊断监听，只观察新事件。
4. 发送一次实际业务请求，确认完整响应模型匹配，而不是只看插件状态。
5. Cookie 分流模式重点检查采集出口、业务出口、`session_id` 是否存在，以及业务响应后是否继续返回目标模型。
6. 触发一次当前票过期或 312，观察备用票是否无需等待即可晋级。

`检查已保存配置` 只检查配置和宿主账号绑定，不发送模型请求，也不探测代理。

## 8. 实测边界

- 同一粘性出口曾连续保持 `87.91` 分钟未换 IP，但未完整跑到 180 分钟。
- 6 张 `292 + gpt-6-astra` 分别持续 `6.05、5.15、5.00、4.11、1.13、1.13` 分钟，之后变为 `312 + gpt-5.6-luna`。
- 无 Cookie 换出口失败历史对照为 `3/3`。
- 带完整 Cookie、保持同一 `session_id` 的跨出口方案曾连续成功 `4/4`。
- 292 何时结束由上游决定。插件能做的是提前准备、快速替换、异常重采，不能本地保证每次一定出 292 或固定持续 5 分钟。

## 9. 常见问题

- 一直显示“生成器不可用”：检查生成器地址和第一层代理是否能访问该域名。
- 一直显示“地区被阻止”：出口落在 `HK` 或地区查询失败；重新获取出口。
- Cookie 票据未生效：确认打票响应确实提供 Cookie，且 `session_id` 非空。
- 备用票不出现：确认 Cookie 模式、备用票开关和提前量正确，并查看诊断中的采集、复验错误。
- 292 仍会变化：代理出口未变时也会发生，说明是上游 292 生命周期变化，不是插件本地 TTL 能解决。
- 升级插件：下载同架构新 `.s2plugin` 后直接上传升级，配置会保留。

插件不包含账号、代理凭据、API Key、STATE、数据库或签名私钥。上游 Overload、429、账号配额和模型策略变化仍可能影响可用性。
