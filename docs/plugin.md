# STATE Kit 插件使用指南

本指南只针对独立插件版，适用于官方 Sub2API `v0.2.7`。插件不修改宿主源码，安装包是 `.s2plugin`。

## 1. 获取代理 API

使用 B2Proxy 注册入口：[https://www.b2proxy.com/signup?code=FF10AB](https://www.b2proxy.com/signup?code=FF10AB)

登录后按以下参数创建提取链接：

| 选项 | 设置 |
| --- | --- |
| 国家和地区 | `GLOBAL` |
| 提取数量 | `1` |
| 代理协议 | `HTTP/HTTPS` |
| 数据格式 | `TXT` |
| 分隔符 | `\r\n` |
| 会话类型 | `黏性IP` |
| IP 时长 | `180` 分钟 |
| 提前更换 IP | `否` |
| 代理主机 | `主机:端口` |

点击“生成 API 链接”，复制完整的 `.../gen?...` 地址。插件配置里直接粘贴这个地址，不要额外拼接账号密码，也不要在地址后加 `#` 锚点。

必须保留这些会话参数：

```text
proto=http&stype=txt&sessType=sticky&sessTime=180&sessAuto=0
```

`sessTime=180` 表示购买 180 分钟粘性会话。必须同时使用 `sessAuto=0`；实测 `sessAuto=1` 会在约 18.7 分钟提前更换出口，无法用于维持 180 分钟票据。出口失效后的自动恢复交给插件处理，不要开启供应商的提前换 IP。

## 2. 配置第一层代理

在 Sub2API 的 **IP 管理 / 代理管理** 中添加一个可用的固定 HTTP(S) 或 SOCKS5(h) 代理，然后在插件里选为“第一层代理”。

代理生成器模式的实际链路是：

```text
插件 -> 第一层代理 -> 生成器 API
插件 -> 第一层代理 -> 生成的 180 分钟粘性代理 -> ChatGPT
```

因此第一层代理必须支持连续转发；只填生成器 API、不填第一层代理时，生成器模式不能正常工作。第一层代理和生成的粘性出口是两层，不是二选一。

## 3. 安装插件

1. 从最新 Release 下载 `trusted-publisher.yaml`，把其中 `state-kit-local-v1` 公钥合并到 Sub2API 现有的 `config.yaml`。不要用示例文件覆盖原配置。
2. 重启一次 Sub2API 应用服务，使公钥生效。
3. 在 **插件管理** 上传 `sub2api-state-kit_plugin_v4.1.0_linux-amd64.s2plugin`。
4. 确认发布者签名受信任，启用 STATE Kit，灰度设为 `100%`。
5. 如果已启用官方 OpenAI OAuth Transport 或其他同类 transport 插件，停用它。同类插件只能启用一个。

## 4. 插件配置

打开 **插件管理 → STATE Kit · 账号级票据 → 配置**，建议首次按下面配置：

| 配置项 | 建议值 |
| --- | --- |
| 第一层代理 | 选择第 2 步添加的固定代理 |
| 代理生成器 API | 粘贴 B2Proxy 生成的 `.../gen?...` 地址 |
| 生成器阻止国家或地区 | 保留 `HK`；需要时再追加其他两位代码 |
| 优先复用账号上一轮可用出口 IP | 开启 |
| 票据有效期 | `180` 分钟；可按实际使用方式缩短 |
| 提前续期 | `120` 秒 |
| 生成器出口有效期 | `180` 分钟 |
| 每轮最多尝试 | `8` |
| 尝试间隔 | `10` 秒 |
| 失败后冷却 | `300` 秒 |

然后添加账号：

1. 出口模式选择 **代理生成器**。
2. 套餐选择 **Pro（292）** 或 **Team（332）**。
3. 目标模型填写实际使用的模型，例如 `gpt-6-astra`。
4. 打开该账号的 STATE 开关，保存配置。
5. 等待状态显示“可用”，再用实际业务请求核对返回模型。

插件会同时检查 STATE 长度、完整响应模型和固定出口。香港及无法确认地区的出口不会用于打票；收到 312、返回模型不符或出口失效时会重新采集。续期期间旧票据继续服务，新票据复验成功后才替换。

## 5. 验证是否生效

- 票据列表显示“可用”且剩余时间接近 180 分钟，只说明插件拿到了本地票据。
- 业务请求完整返回目标模型，才说明本次链路可用。
- 打开“实时诊断监听”可查看采集阶段、出口 IP、292/312、HTTP 状态和响应模型。
- 不要只依据“测试已保存配置”；它只检查插件和宿主配置，不代替真实模型请求。

180 分钟是本地上限和供应商会话设置，不是对上游的硬保证。若供应商提前换 IP、出口被限制或上游改变策略，插件会按异常检测重新获取，不会把旧票据无限续用。

## 6. 实测结论

- `sessTime=180&sessAuto=0` 的同一出口已实测连续保持 `87.91` 分钟未变。
- `sessAuto=1` 会在会话中提前换出口；其中一次在第 `18.74` 分钟发生变化。
- 6 张 `292 + gpt-6-astra` 分别持续 `6.05、5.15、5.00、4.11、1.13、1.13` 分钟，之后上游变为 `312 + gpt-5.6-luna`。
- 跟踪期间出口 IP 没有变化，所以变回 312 是上游 292 状态变化，不是代理掉线或换 IP。
- 受控切换测试确认：同一张 292 在采集出口上继续返回 `gpt-6-astra`，换到第一层代理出口立即变成 `312 + gpt-5.6-luna`，切回采集出口后又恢复。
- `10` 分钟可能成功，但本轮实测最长连续样本为 `6.05` 分钟；不能承诺单张 292 保持 180 分钟。

因此，180 分钟粘性 IP 解决的是固定出口问题；292 的持续由上游决定。不能在打票后切换出口或直连，实际业务请求必须继续走同一生成粘性出口。插件会保留异常重采，不能通过单纯增大本地票据有效期让已经失效的 292 继续有效。

## 7. 常见问题

- 一直显示“生成器不可用”：检查第一层代理是否在线，以及生成器 API 是否能在该第一层代理下访问。
- 一直显示“地区被阻止”：出口落在 `HK` 或地区查询失败；重新获取出口。
- 292 仍会变化：供应商会话可能提前失效，上游也可能返回不同状态；插件只能缩短异常持续时间和自动恢复。
- 更新插件：下载同架构的新 `.s2plugin` 后，按宿主插件管理升级；配置会保留。
