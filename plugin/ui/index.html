总开关与代理链路

总开关和账号开关均开启时，该账号才会获取、使用票据。

旧模式要求采集、复验、业务请求始终走同一个生成粘性出口，适合先前的 180 分钟同出口方案。Cookie 分流模式会在采集阶段保存响应 Cookie 和 session_id，业务请求再通过独立业务出口发送这些会话信息；因此打票出口和业务出口不再强制相同。

旧模式下，第一层会先连接生成器返回的第二层代理，采集、复验和业务请求共用同一个出口。Cookie 分流模式下，若没有单独填写业务固定代理，业务请求会使用这里的第一层作为出口。

支持 HTTP、HTTPS、SOCKS5 和 SOCKS5H。地址中的 {random} 或 {sid} 在每次尝试时替换为随机会话值。请填写自己的代理，不在此处填写账号 Token。

打票方式只决定 Cookie 会话从哪里取得。生成器模式可配合“优先复用上一轮出票 IP”；S5/HTTP 固定采集代理模式适合已有固定采集链路的场景。两条链路都会先检查出口国家/地区，香港和未知地区会被拒绝。

支持 HTTP、HTTPS、SOCKS5 和 SOCKS5H。选择打票方式为 S5/HTTP 时必填；如果同时配置了第一层代理，连接顺序为第一层 → 采集代理 → ChatGPT。生成器模式不需要填写此字段。

业务请求的出口。留空时使用第一层 IP 管理代理；也可以填写独立的 HTTP/HTTPS/SOCKS5/SOCKS5H 业务代理。这里不再要求与采集出口相同，但仍会拒绝香港和未知地区。

开启后，当前票据剩余时间小于“备用票提前量”时，插件会在后台获取一张新票据并放入备用票槽；当前票失效或被上游判定为 312/模型不符后，备用票会自动顶替，避免业务请求等待新票据。备用票只保留一张，验证成功前不会替换当前票。

旧模式下，插件通过第一层代理调用此 API，读取返回的 host:port，并在采集、复验和业务转发期间固定使用该出口。Cookie 模式的打票方式选择“代理生成器 API”时，生成出口只用于采集和复验，业务请求改走上面配置的业务固定代理或第一层。

B2Proxy 使用 180 分钟粘性 IP 时，请把“提前更换 IP”设为“否”并保留 sessTime=180&sessAuto=0；sessAuto=1 可能在会话中途更换出口。

填写 ISO 两位国家代码，逗号分隔；香港 HK 始终保留，未知出口地区也会被拒绝并重新生成。

开启后，每个账号打票时先复用该账号上次通过复验的生成器出口 IP；复用失败会自动回退到代理生成器获取新出口。旧模式下仍会重新检查采集/业务出口一致性；Cookie 模式下会检查采集出口地区，并重新完成 Cookie 会话复验。

关闭并保存后停止票据获取与注入；正常请求继续转发。
